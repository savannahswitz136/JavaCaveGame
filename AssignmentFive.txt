I spent some time learning about abstract classes in relation to Java. 
The sources I read used the analogy of an abstract class being like “incomplete 
blueprints.” They themselves do not create objects but rather create the “blueprint”
or theme of other classes in relation to each other. That is still not a 
concrete definition, however. An abstract class may contain Abstract methods, concrete methods, 
constructors, and instance variables. An Abstract method does not contain a “body” 
and therefore forces the subclasses to provide implementations themselves.
 Concrete methods can also be declared within an abstract class, 
and these are regular methods with a body and create shared 
functionalities with the subclasses. The main reason to use an 
abstract class is that the create conneuity in subclasses by defining a 
“contract” that they have to follow. Due to this the prevent incomplete 
classes being made as well as reducing duplication in code.
